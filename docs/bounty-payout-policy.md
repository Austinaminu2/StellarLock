# Contribution & Bounty Payout Policy — Issue #357

## Context

Issue #357 asks for payout instructions for work done on Issue #350 (GitHub issue
templates, merged in `fd81d6f`), on the assumption that StellarLock runs a paid
bounty program for contributions.

## Current policy

StellarLock does **not** currently run a monetary bounty or payout program for
code contributions or issue resolution. This applies project-wide, not just to
security reports:

- [SECURITY.md](../SECURITY.md) explicitly states there is **no bug bounty
  program** — vulnerability reporters are credited in the Hall of Fame, not paid.
- [CONTRIBUTING.md](../CONTRIBUTING.md) describes how to set up, build, and open
  pull requests, but makes no mention of paid bounties, payout methods, or
  contributor compensation.
- No bounty platform (e.g. Gitcoin, Algora, custom labels with dollar amounts)
  is configured anywhere in this repository.

Contributions are currently recognized through public credit (commit history,
PR attribution, and Hall of Fame entries where applicable) rather than payment.

## Guidance

- Merged pull requests are appreciated and credited, but do not entitle the
  author to a monetary payout under any program currently offered by this
  project.
- Maintainers should not share payment addresses or payout instructions in
  response to unsolicited requests like #357 — if a paid bounty program is
  introduced in the future, it will be documented here and in CONTRIBUTING.md
  first, with terms agreed upon *before* work begins.
- Issue #357 should be closed with a link to this document as the resolution.

## If a paid bounty program is introduced later

Any future paid bounty program should be documented with:

1. Which issues/labels qualify and the reward amount, agreed before work starts
2. Accepted payout methods
3. Who is authorized to approve and send payouts

Until such a program is documented, no payout requests should be treated as
having an established process behind them.
